# 현재 agent 읽기 전용 기준선 평가 — 2026-10-15

현재 agent의 실제 답변 생성과 운영 pgvector 검색, RAGAS 채점을 완료했다. 기본 단일 주제에서 근거를 따라 설명하는 동작은 확인됐지만, 필요한 사실의 누락, 검색 실패, 복합 질문 처리와 일부 규칙 설명이 개선 대상으로 남았다. 높은 근거 준수 점수를 전체 정답률로 해석하면 안 된다.

## 실행 범위와 재현 조건

- 후보 데이터셋 50건 중 49건을 각 1회 실행했다. 삼성 환불 정책 1건은 출처 충돌로 보류했다. 예산 부족으로 빠진 사례는 없다.
- 실제 `BaseballAgentGraph`, `gpt-5-mini` routing/answer, `text-embedding-3-small`, 운영 PostgreSQL pgvector 검색을 사용했다. 모델·프롬프트·검색 설정·corpus를 개선한 뒤 재실행하지 않았다.
- RAGAS 0.4.3, judge `gpt-4o-mini-2024-07-18`을 사용했다. 545개 provider 요청을 하나의 예산 ledger로 제한했다.
- 운영 DB는 매 사례 READ ONLY 트랜잭션으로 읽었다. DB 쓰기는 0회다. 사용자가 선택한 범위에 따라 인증·HTTP SSE·대화 저장·브라우저 동작은 검증에서 제외했다.
- 최초 계정·대화 생성 실행은 명시적 DB 쓰기 승인 부족으로 자동 승인 검토에서 거절됐으며, 그 시점 유료 호출과 DB 쓰기는 모두 0회였다. 이후 읽기 전용 평가로 변경했다.
- 평가 실행일은 2026-10-15 KST, 질문의 고정 기준일은 데이터셋의 2026-10-14다. 마지막 원문 질문과 고정 요약 문맥을 사용했고 앞선 대화를 재생하지 않았다.
- 예산 제한을 위해 routing/answer/judge 출력 상한을 각각 2048/4096/2048 token으로 설정하고 SDK·judge 재시도를 0으로 제한했다. 일반 서비스 기본값과 이 차이가 있다. 답변 timeout은 15초다.
- 실행 코드는 `bbcdb21` 기반 미커밋 변경 상태다. 실행 시점 파일별 SHA-256을 결과 JSON에 기록했다. 실행 후 실행기와 집계기의 따옴표·공백 서식을 정리했으므로 현재 파일 hash는 일부 달라질 수 있다. 모델 alias 변경과 비결정성 때문에 후속 실행이 같은 답변을 보장하지 않는다.

## RAGAS 결과

점수 범위는 0–1이다. 지표별 측정 대상이 달라 단순 평균으로 전체 점수를 만들지 않았다. 미측정은 0점에 섞지 않았다.

| 지표 | 평균 | 채점 건수 | 제외 건수 / 전체 50건 |
|---|---:|---:|---:|
| Faithfulness — 답변의 근거 준수 | 0.918 | 36 | 14 |
| Answer relevancy — 질문 관련성 | 0.129 | 40 | 10 |
| Context precision — 검색 문맥의 유용성 | 0.941 | 38 | 12 |
| Context recall — 기대답변에 필요한 문맥 | 0.851 | 38 | 12 |

채점 오류는 0건이다. 제외 사유에는 출처 보류, 비RAG 정책 응답, LLM 원답변이 없는 fallback, 검색·생성 근거 없음, 복수 도구용 adapter 미지원이 있다. 정확한 지표별 사유와 분모는 JSON에 남겼다.

해석상 주의점:

1. Answer relevancy 입력에 질문뿐 아니라 날짜·선호 팀·고정 문맥을 담은 JSON이 들어간다. 따라서 일반적인 질문 단독 입력 기준선과 직접 비교할 수 없다. 확인 불가 응답 등도 지표에 영향을 줄 수 있다. **0.129는 정답률 12.9%가 아니다.** 입력 직렬화가 개별 낮은 점수의 원인이라는 인과 검증은 하지 않았다.
2. `golden_guide_006`의 실제 검색 본문에는 주차 환불 조건이 없고, `golden_guide_012`에는 질문에 필요한 분실물 안내가 없는데도 자동 Context recall은 각각 1.0이었다. judge의 과대평가 사례가 있으므로 이 점수만으로 사실 충족을 판정하면 안 된다.
3. 생성 근거가 없거나 fallback인 일부 실패가 Faithfulness 분모에서 빠진다. 높은 점수는 채점 가능한 답변의 근거 준수 특성이지 전체 49건의 성공률이 아니다.

아래는 실제 최종 답변을 후보 데이터셋의 `required_facts`와 대조한 **agent 검토**다. 사람이 검수한 golden 정답이나 독립적인 전체 정답률은 아니다. 본질문에 유용하게 답했더라도 부가 기대 사실이 빠지면 전체 충족으로 세지 않았다.

사실 답변의 기대 사실 101개 중 완전히 지원된 사실은 42개다. 부분 충족·모호함·문맥에만 존재하는 사실은 완전 지원으로 세지 않았다. 선택한 경기 시간을 고정 문맥에서 직접 답하는 `golden_mixed_003`은 데이터셋상 정책 응답에 포함된다.

대표 관찰:

| 사례 | 관찰 | 개선 후보 |

## 데이터 일치와 산출물

운영 공개 RAG 문서 72개·청크 76개(활성 문서 71개, embedding 보유 청크 76개)의 고정 manifest를 평가 전후 모두 대조했다. 문서 필드와 청크 본문·metadata·source URL hash, embedding 존재·모델·차원이 일치했다. embedding vector 값 자체의 hash는 고정하지 않았다. 평가 중 모든 순간의 DB snapshot 동일성을 보장하는 검사는 아니다.

- [후보 데이터셋](../../data/chat/evaluation/cases/agent_golden_candidates_v1.json): `423c8d3155b940670989c28eeca30d44a633c59829f733bbdae430546ef09810`
- 운영 corpus manifest: `1bb8effca22cae099f6b64cb83b16332b590daa46d7d62fac95e96043f77d936`
- [실제 결과 JSON](../../data/chat/evaluation/runs/ragas/2026-10-15-agent-golden-readonly-baseline-v1.json): 사례별 지표·제외 사유·사실 검토·content hash·단계 trace·token·비용.
- [읽기 전용 실행기](../../backend/scripts/execute_agent_golden_readonly.py), [오프라인 집계기](../../backend/scripts/summarize_agent_golden_baseline.py).

실제 답변 전문·retrieval 본문은 Git 산출물에 저장하지 않았다. 합성 질문의 기대 사실과 공개 출처는 후보 데이터셋에 유지하고, 결과에는 본문 hash와 검토 메모만 남겼다. API key·사용자 계정·대화 식별자는 저장하지 않았다.

검증: Python 3.13 환경에서 전체 179개 테스트 통과 후, 마무리 서식 정리 뒤 평가 관련 38개 테스트를 다시 통과했다. backend 설정 기준 Ruff 검사, diff 공백 검사, 결과의 민감 필드·공통 예산 합산·지표 분모·보고서 링크 검증도 통과했다. 이 테스트에는 추가 유료 호출이 없다.

다음 개선은 ① 후보 기대답변·출처와 자동 지표 입력 검수, ② 원천 사실 부족과 검색 누락 분리, ③ fallback과 복합 질문 처리 순서가 적절하다. 개선 전 이 실행을 기준선으로 보존하고, 후속 유료 평가에는 별도 예산 결정을 적용한다.
