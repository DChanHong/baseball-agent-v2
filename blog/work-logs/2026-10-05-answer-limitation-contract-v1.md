# 답변 limitation 계약 개선 작업 기록

> 날짜: 2026-10-05
> 범위: 모델 입력·출력과 서버 검증 계약 일치
> 상태: 구현·합성 검증 완료, 실제 모델 QA 미실행
> 커밋: 미실행

## 왜 이 작업을 했는가

최소 trace의 실제 실행에서 야구 지식 검색은 성공했지만 최종 답변 검증이
실패했다. 약 12.9초 걸린 모델 호출 결과를 버리고 기본 답변으로 전환했다.
기존 예외 로그를 대조해 허용 목록 밖 limitation 반환을 원인으로 확인했다.
이번 작업에서는 속도보다 사용 가능한 모델 답변의 안정성을 먼저 다룬다.

## 작업 전 상태와 결정

서버는 Tool과 evidence에서 허용 목록을 계산했지만 모델에는 그 전체 목록을
독립적인 필드로 전달하지 않았다. 모델이 자연어 설명과 metadata 코드를
구분하도록 입력 계약과 prompt를 명시한다.

- 기존 허용 규칙과 엄격한 검증·fallback을 유지한다.
- 출력은 list[str]로 유지하고 입력에 `allowed_limitations`를 추가한다.
- 모델이 새로운 코드를 만들면 거부한다. 삭제·변환·재시도하지 않는다.
- 모델, timeout, 검색 근거 상한과 streaming은 변경하지 않는다.

## 구현한 것

- bounded evidence에서 허용 목록을 계산하고 모델 입력에 전달
- 모델 입력에 전달한 바로 그 목록으로 출력 검증
- 코드 선택과 자연어 설명을 구분하는 prompt·field description
- AnswerContractError의 세 가지 실패 코드
- answer_validation trace와 최종 fallback_reason의 구체적 분류
- 오류 메시지에 모델 생성 코드를 복사하지 않음

## 검증

`test_answer_generation_service.py`와 `test_agent_trace.py`를 보강했다.
허용 코드 조합·빈 목록·근거 상한·잘못된 코드·schema·evidence ref 오류를
검증하고 timeout·동시 요청·SSE 흐름 회귀도 확인한다.
Fake chain으로 생성 결과를 제어했다. 자연어 품질 향상이나 실제 실패율 감소를
증명한 결과는 아니다. 최종 실행 결과는 아래 검증 메모에 기록한다.

## 블로그 소재

- structured output도 list[str] 값의 요청별 의미를 자동 보장하지 않는다.
- 서버만 아는 허용 목록을 모델도 볼 수 있게 입력 계약을 맞췄다.
- 불필요한 fallback을 줄이는 목표와 검증을 느슨하게 하는 선택을 구분했다.
- 모델 호출 성공과 출력 계약 검증 성공을 별도 단계로 관측했다.
- 실제 효과는 같은 질문의 모델 재실행으로 확인해야 한다.
